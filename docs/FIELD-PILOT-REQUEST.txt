En el repo SanLean17/AsistenteBibliotecario, implementar un BLOQUE MUY GRANDE llamado:

FIELD PILOT V1 — OFFLINE-FIRST + ESCALA + RECUPERACIÓN + MANUALES + SIMULACIÓN REAL

Objetivo: transformar la RC1 actual en una versión de campo preparada para una prueba escolar prolongada de varios días/semanas, sin backend, sin Supabase/Firebase y sin servicios pagos. La prioridad no es agregar muchas funciones nuevas, sino hacer que el producto sea resistente, entendible, portable, recuperable y usable bajo condiciones reales de escuela.

ANTES DE EMPEZAR
1) Verificar el commit final de RC1.
2) Revisar GitHub Actions y confirmar qué está verde/fallando/flaky.
3) No ocultar errores con continue-on-error.
4) No desactivar tests importantes.
5) Mantener muy pocos commits coherentes; idealmente un commit final grande o una pequeña serie bien definida.
6) No considerar terminado hasta que el commit final tenga CI completamente verde.

FASE 2 — OFFLINE-FIRST REALISTA
==================================================

El objetivo es que operaciones LOCALES sigan funcionando sin conexión una vez cargada la app.

Evaluar si es seguro implementar una PWA/service worker.

Si la arquitectura lo permite sin introducir riesgo:
- crear manifest web app;
- service worker simple y auditable;
- cachear solamente assets locales versionados;
- NO cachear respuestas bibliográficas externas como fuente autoritativa silenciosa;
- usar estrategia clara para HTML/CSS/JS;
- evitar quedarse pegado a versiones antiguas después de deploy;
- integrar con el versionado de caché existente.

Si una PWA completa introduce demasiado riesgo, implementar solamente una estrategia offline segura y documentada.

Objetivo mínimo offline:
- abrir catálogo local;
- buscar localmente;
- ver fichas;
- Mostrador;
- préstamo;
- devolución;
- reservas ya almacenadas;
- inventario;
- estado físico;
- jornada local;
- etiquetas si assets están disponibles;
- Mi biblioteca.

Operaciones que requieren red deben degradar bien:
- Open Library;
- Google Books;
- cualquier consulta bibliográfica externa.

Mensaje esperado:
“Sin conexión. Podés seguir trabajando con los datos locales y completar esta ficha manualmente.”

Nunca mostrar error técnico genérico si se conoce que es falta de conexión.
